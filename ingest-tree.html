CROSS-LINKS
├── Contact merge / unweld  ⟷ restructures PERSON + HOUSEHOLD (admin decision, never automatic)
├── propagate_contact_fields  ⟶ an email/phone edit on one record propagates to every
│                              record on the same PERSON
├── Conversion matcher  ⟵ reads CHANNEL (canonical) + RECORD (raw) forms — tolerant of
│                        the record-layer inconsistency shown above
└── Go schemaguard  ⟶ fails Go startup if Django migrations change the whitelisted tables

Entry point → database table write map

For each entry point: every database table it writes, and how. ORM+sig = Django ORM create — pre/post-save signals fire, so Person, channels and household resolve automatically. chokepoint = written via ContactChannel.get_or_create_channel (canonical keys). raw SQL / GORM = bypasses Django (no signals — normalisation re-implemented in Go). — = this entry point never touches that table.
