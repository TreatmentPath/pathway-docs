## How it was run

The deployed checkout (`main` @ `631955f4`) did **not** contain the rehearsed code
(0 matches for every new guard/flag), so the runbook was executed from a synced copy
of the rehearsed working tree (`/root/identity-repair-code` on the host) inside a
throwaway container built from the deployed image — same dependencies, same network,
prod `.env`, `entrypoint.sh` bypassed (`run.sh`). No file under `/app` of the running
app was touched; no migration was applied (5 pending in the tree are unrelated and one,
`dentallyIntegration.0168`, must ship with its Go change). The secrets copy used by the
runner was deleted afterwards.

No dump was taken by me (backup handled by the owner). The "untouched control" for the
row-by-row verifiers was `facts_before.json` — a read-only dump of every identity fact
taken before the first write. The Dentally sync was live throughout (a Person was
created 20 s before the baseline); existing rows keep their `person_id` on upsert, and
the audit's `NEW` column stayed 0.
